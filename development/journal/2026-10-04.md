### Key findings

The API spike confirmed that the Companies House API can provide the core data required for the Q1–Q10 MVP.

Important findings included:

- The API rate limit is 600 requests per 5 minutes.
- Most standard company reports require relatively few API calls.
- Q8 (director network analysis) is the main source of additional API calls.
- Some endpoints represent "no data" with HTTP 200 and an empty result, while others return HTTP 404.
- API latency is low enough that the 30-second report target appears feasible on the API side.
- Caching and recorded fixtures will be important for development and evaluation.
- Officer identity matching has limitations because the same person can appear under different Companies House officer IDs.
- Manual checks against the Companies House website matched the API-based findings for the companies tested.

### Decisions made

The main architectural decisions established during Phase 0 were:

1. Use MCP rather than direct function tools.
2. Use LangGraph for agent orchestration.
3. Start with one API LLM and compare open-weight models later.
4. Use SQLite with a 24-hour TTL for caching.
5. Use the official Python MCP SDK / FastMCP.

The project will use a phase-by-phase backlog rather than creating the entire future implementation backlog at once. Future issues will be added as each phase becomes active.

### What remains open

Phase 0 clarified the API and project foundations, but several questions remain for later phases:

- What production limit should be placed on Q8 director-network expansion?
- How many verifier loops are actually required?
- Should the planner always run Q1–Q10 or skip questions that are not needed?
- How well does the agent perform against the defined success metrics?
- How do different models compare on quality, cost and latency?

These will be answered through implementation and evaluation rather than further planning.
